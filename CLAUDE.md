# tf3-save-mapper

Read-only command-line tool that draws an SVG map of a Transport Fever 3 `.sav`. Unofficial fan tool, licensed MIT OR Apache-2.0. Rust, as a Cargo workspace: `tf3-save-mapper-core` (container, header, edges, instances, terrain and contours, install reader, SVG writer with a module per layer; no CLI code) and the binary crate (arguments, file output). The binary is `tf3map`, built from the `tf3-save-mapper` crate in `crates/tf3-save-mapper`; the core is `crates/tf3-save-mapper-core`. Both are `publish = false` until the user decides on crates.io.

Positioning: use a `tf3-` name; write "Transport Fever 3" only in the description and topics. The README carries an "unofficial, not affiliated with Urban Games" line.

## Workflow

- `main` is protected by a ruleset: no deletion, no force push, changes only through a pull request. Work on a branch; never commit to `main`.
- Do not push, open a PR or change repo visibility unless asked.
- Commits end with the Co-Authored-By line from the session's attribution reminder.
- Stay in this repo. Changes to `tf3-save-format` or `tf3-save-editor` only through a handoff the user requests.
- `gh` from snap prints nothing in this environment; run `/snap/gh/current/gh`.

## Rules for what goes in

- Never commit `.sav` files, decompressed streams, or previews or maps of other people's saves. The exception: a zoomed-in crop of a save published in the mod.io catalogue may go in `docs/images/` as an example, cited by mod.io id only (the whole map or a preview still may not). `.gitignore` blocks the common forms (including `*.svg` and `*.png` outside `docs/images/`). Name files in `git add`; never `git add -A` or `git add .`.
- Never write or modify a `.sav`.
- Saves hold other people's local details. Company names default to the account display name; a mod's Lua error text can contain its full install path with the account name. Output, docs, tests and commit messages must mask them: `<name> Transport`, `<path>/mod.io/10640/mods/<id>/...`.
- Cite catalog saves by mod.io id only. Tests committed to the repo use a hand-built minimal synthetic stream. A golden test against real saves reads the path from an environment variable and skips when it is unset.
- Use the game's internal names (`cement`, `vegetables`, `ship`); the list is in `tf3-save-format/docs/glossary.md`.
- Offsets move between saves: find structures by pattern, never by fixed offset.
- Write the reader from the format notes in our own words. Never copy text or code from tf3-save-editor's `FORMAT.md`; credit it if used.
- The icons in `crates/tf3-save-mapper-core/icons/` are copies of tf3-save-format's `tools/icons/` (our own drawings, same licence), built in with `include_str!`. Change them there and copy them over; a new industry key also needs a line in `ICONS` (`svg/industries.rs`). `.gitignore` lets `*.svg` in that folder through.

## Testing

- Committed tests use a hand-built stream (`crates/tf3-save-mapper-core/tests/common/mod.rs`): header, model table, terrain and heightmap, edge table, decoy, one industry instance, two vehicles, a road maintenance building, a mod's boathouse, a mod industry's hangar (an `industries/` piece with no main model; its instance comes last so the others keep their `data-slot`), lane table, free-id list. Keep heightmap runs short (no long ascending run of u32 words near the stream's end, or the free-id search takes it). Keep its floats varied: with all-equal heights a misaligned read can pass the plausibility checks and make the table's first record ambiguous.
- `tests/golden.rs` runs on a real save when `TF3_MAPPER_TEST_SAVE` is set (and checks the edge count against `TF3_MAPPER_TEST_EDGES` if set) and does nothing otherwise. Never write that path into a committed file.
- `tf3map` is the only map drawer: tf3-save-format removed its Python prototype (`terrain_map.py`, `terrain_vector.py`) in commit `fa6b605`, and its tools, notes and skills call `tf3map`. A change to the drawing is made and checked here, not ported from there.
- Check a change against the previous build: build `main` (or the last release) into a scratchpad worktree, run both on the same real saves with the same options, and compare the SVGs element by element. Key on `data-model`/`data-key` with `data-x`, `data-y`; outline runs and border loops compare after normalising each loop's start; compare terrain paths by level, edges per edge (positions within 0.2 m and the curved/straight choice, after the edge filters: free-id list, lane table, loose industry pieces, sidings; counts alone hide mismatches). For `--raster`, `--mpp` and `--png`, decode the PNG (the `terrain` layer's data URI, or the file) and compare pixel by pixel. Everything the change does not mean to touch must come out the same; strip the view record's `generator-*` attributes and the rest should be byte for byte. Use saves that exercise the change (the mined index in tf3-save-format's `local/mined/` finds them), and run several in parallel in the background.
- Keep the raster arithmetic as it is: `.powf(0.5)` in `svg/raster.rs`, not `.sqrt()` (the two can differ in the last bit, and truncation to bytes turns that into flipped pixels), floor division when filling in the grid below 4 m per pixel, truncation to bytes. The pixel checks and PNG fingerprints in `tests/synthetic.rs` and tf3-save-format's `docs/terrain-drawing.md` rest on it.
- The view record writes each non-default setting under the prototype's name where it had one (`contour-step`, `index-every`, `bands`, `grid`, `grid-step`, `grid-lines`, `industries`, `terrain`) and ours for the rest (`depots`, `stations`, `rose`, `zoom`, `vehicles`, `coverage`, widths). Keep those names; a new setting gets a name that clashes with none of them.
- For mod depots (`--mods`), use saves with boathouses (`ingo_bootsschuppen.mdl` instances; the mined index's `ingo_boathouse_asset`), roundhouses (`mav2002_rl_wanne.mdl`; 6417698, 6495445) and modern depots (`maikc_depot_modern_f1_tuer.mdl`; 6420436, 6487589 has both). A mod being in a save's `mod_list` does not mean one is built: count the instances. Without the mods folder our output must equal the previous build's, `generator-*` attributes stripped as above: run ours with `HOME` pointed at an empty folder and `--game DIR` to check that.
- The prototype is still in tf3-save-format's history, last at commit `4eb3fba` (`tools/terrain_map.py`). "The prototype" in code comments and tests means that script. For a reference compare, run `git archive 4eb3fba tools` in the sibling `tf3-save-format` repo, unpack it into a scratchpad and run it with `python3 -I`; it takes about 90 s for a mid-size save. On a crop, shift its coordinates by the corner of our `viewBox`. With `--png` its pixels differ from ours only round edges whose lanes give another width than its template; check that each differing pixel lies within a brush width of such an edge. The differences that were ours by choice: edge widths from the save's lanes (it used the template, or 16 m and 4 m); one 1.5 m outline width (it scaled outlines and the landing clearance by metres per pixel); our picture is the exact box (its was one pixel wider and taller, so a crop kept 1 to 2 extra edges, its grid lines ran 8 m longer and its default rose sat a few metres off); our `viewBox` stays the whole map at an `--mpp` that does not divide it; `data-slot` counts every instance record (it counted only the prefixes read together); a coverage circle's group is `coverage-SLOT` (it reused the depot's id); on a crop we draw from everything within 500 m and write what reaches into the view by its drawn shape (it kept every depot footprint within its coverage radius, and built borders and anchors from what it kept); we draw a boathouse dot without the mods folder; our `--vehicles` works without `--crop`; its view record had `source` and `generated-utc`, which we leave out, and no `generator-version`; it drew `perron_5_underpass`, the head pieces and the `s2` side building of era a only, and no `small_new` or two-sided stops.
- Data quirks seen in real saves, not bugs: a few nodes (up to about 1.5 %) have two positions because leftover records reuse ids, and airport runways can reach past the map edge. An edge's lane widths can differ from today's template (`town_new_small` 14 m against 16 m in an older save); draw the save's. Numbers in the install's `.mdl` and script files can carry exponents (`2.28882e-07`); a reader that stops at `e` drops or shrinks pieces.

## Game install

- Never read, `strings`, dump or grep the game's native binaries: the `TransportFever3` executable, the bundled `.so` libraries, `model_editor/ModelEditor`.
- `base/content/` archives may be read for facts only, under the conditions in `tf3-save-format/CLAUDE.md` ("Game install"): no republishing string tables, no fonts, no music, no meshes or textures, and never bundle base data in the tool.
- `tf3map` reads the install at run time (`install.rs`: station `.mdl` boxes, depot and industry script ground faces) and keeps nothing. Tests never need an install. It reads a mod's depot script, and the `.mdl` files of a depot built from pieces, from the mod.io mods folder the same way (`Mods`), and never writes there.
- `.claude/hooks/tf3-install-guard.py` (copied from tf3-save-format) blocks the common ways of reading the binaries. It also fires on any command that mentions the install by name and pipes through `grep` without `-I`; put such text in a file or use the Edit tool.

## Dependencies

Standard crates are fine if their licences are permissive. Tell the user about any heavy or unusual crate before adding it. Keep `rust-version` and edition in line with the installed toolchain.

## Reference

The format notes and the Python readers are in the sibling `tf3-save-format` repo. Readers in its `tools/`: `street_edges.py` (edges), `model_instances.py` (instances; its `slot` is our `data-slot`, the record index), `terrain_heights.py` (terrain record and heightmap), `save_header.py`, `tf3save.py` (container). Read `tools/README.md` and `docs/README.md` there first, and use `tools/facts_index.py --outline` rather than whole-note reads. Relevant notes: `docs/road-network.md`, `docs/compass.md` (x east, y north), `docs/entity-names.md`, `docs/station-pieces.md`, `docs/terrain-drawing.md` (what the drawing was checked against). A gap or bug in the drawing is fixed here; a reader or format bug also gets a handoff there when the user asks for one. Known drawing gaps are in `docs/gaps.md`: add an entry when one is found, delete it when it is fixed.

Drawing preferences: omit labels rather than move them; compass rose lower-right; the grid is drawn by default (`--no-grid` leaves it out); one outline width (1.5 m); no inner lines; station colours brown, grey, light grey; plain dark anchors; vector terrain by default.
